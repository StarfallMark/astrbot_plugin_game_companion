# 游戏伴侣

游戏伴侣让 Bot 与用户通过独立 WebUI 一起玩五子棋、中国象棋、井字棋、海龟汤、贪心骰子和你画我猜，同时保留 AstrBot 的正常聊天、人格、生活场景和长期记忆链路。

## 核心行为

- 用户通过 QQ 自然语言邀请 Bot 玩五子棋、中国象棋、井字棋、海龟汤、贪心骰子或你画我猜，由 LLM 工具创建房间；进入房间后的游戏切换和玩法选择都在 WebUI 对话区完成。
- 游戏操作和 Bot 对话都在 WebUI 完成；桌面端游戏区与对话区并列，手机端可切换“游戏 / 对话”视图。
- Bot 根据人格选择简单、普通或困难棋力；贪心骰子中对应稳健、均衡或大胆的风险倾向，玩家不能在网页直接选择。
- 五子棋可选玩家先手、Bot 先手或随机；象棋可选执红、执黑或随机；井字棋可选执 X、执 O 或随机。
- 贪心骰子每局随机先手，双方选择继续掷或收手存分，率先达到 50 分获胜。
- Bot 操作有轻微延迟。五子棋搜索在线程中执行，象棋通过单独的 Pikafish 进程串行计算，井字棋和骰子策略在内存中完成，均不阻塞 AstrBot 事件循环。
- 用户在 WebUI 对话区自然提出“再来一局”时，Bot 直接在原房间重置当前游戏，保留链接、玩家身份、多人席位、访客序号和累计统计，不创建新房间；海龟汤会按当前玩法开始全新题目。
- 六种游戏分别累计统计。切换游戏保留房间链接、玩家、访客序号和权限；进行中的游戏必须明确确认放弃后才能切换。
- 棋类的悔棋以及通用的暂停、继续和认输/放弃都从 WebUI 对话区发起。QQ 只负责创建房间、接收链接和绑定一次性令牌；海龟汤和贪心骰子不支持悔棋。
- 普通走棋和掷骰不调用模型；Bot 出题海龟汤的问答仅调用隐藏裁判，玩家出题海龟汤只向模型提供公开线索与公开回合。房间结束时只为已绑定发言者保存有限对话摘录，不保存完整房间记录。
- 游戏中的 Bot 回复、系统事件和玩家消息只显示在当前房间 WebUI，不发送到 QQ，也不写入 AstrBot 的普通对话历史，避免临时游戏语气影响后续正常聊天。
- WebUI 对话会按当前房间和发言者注入实时游戏状态；匿名观众不读取或写入长期记忆。只有私聊来源且房内仅有一名已绑定访客时才读取该用户的私人陪伴记忆，避免公开回复泄露个人信息。
- 身份确认前不读取该用户的长期记忆或生活场景，也不写入共同经历。
- 普通房间的每位访客进入玩家席前，必须在 WebUI 查看一次性令牌，并在原群聊或私聊中直接发送令牌，或发送“绑定玩家 令牌”；令牌只绑定当前房间的一个访客，使用一次后失效。配置固定 HTTPS 域名并启用受信任浏览器后，用户可以选择让同一浏览器在后续新房间中自动确认 QQ 身份。
- 绑定成功后保存发送者当时的 QQ 昵称/群名片。页面和 Bot 优先显示昵称，同时保留访客序号用于重名区分、交换申请和管理操作；昵称不是权限凭据。
- QQ 中的普通聊天不再注入活动房间状态，仍使用完整陪伴插件链路，不会被其他房间成员的 WebUI 对话干扰。
- 房间结束时按已绑定 QQ 分别保存游戏摘要和有限对话摘录，不保存逐步棋谱或完整房间聊天记录。
- AstrBot 或插件重载时销毁所有活动房间，不恢复未完成棋局。

## 房间权限

插件配置中的游戏管理员与 AstrBot 管理员相互独立。

- 群聊默认只允许游戏管理员创建房间。
- 管理员创建的房间中，所有访客先进入观众席并获得稳定序号。管理员在“游戏管理台”选择一个或多个序号并分别绑定玩家 QQ 后才能开局。
- 普通房间中，只有完成 QQ 令牌绑定的访客才能自行加入玩家席；海龟汤允许已绑定访客加入空余玩家席。创建者不再默认占据首个玩家席。
- 私聊房间采用普通房间规则。
- 管理台展示创建者、访客序号、席位和房间状态，不展示棋盘、棋谱或进行中的海龟汤汤底。管理员可以切换房间游戏，但不能设置棋力或题目。

## QQ 游戏菜单

在 QQ 中发送 `/game 游戏菜单` 可以查看插件当前支持的全部游戏，以及所有群聊合计、所有私聊合计的活动房间数量与配置上限。若 AstrBot 使用了不同命令前缀，请将 `/` 替换为对应前缀。

## 受信任浏览器

受信任浏览器默认关闭，只在 `server.public_base_url` 配置了固定 HTTPS 地址且 `identity.enable_trusted_browser` 开启时生效。Cloudflare Quick Tunnel 等临时域名不会启用长期 Cookie，仍按每个房间的一次性 QQ 令牌流程工作。

用户首次完成 QQ 令牌绑定时，可以在 WebUI 取消“在此浏览器记住我的身份”。选择记住后，服务端生成高强度随机设备凭证；浏览器只通过 `HttpOnly`、`Secure`、`SameSite=Lax` Cookie 保存原始凭证，插件数据目录中的 `trusted_browsers.json` 只保存 SHA-256 摘要、QQ、昵称和有效期。

设备凭证默认有效 30 天，可配置为 1-365 天，每个 QQ 最多保留 8 台设备。受信任浏览器进入新房间后只自动确认 QQ 身份，仍停留在观众席，需要用户主动加入对局；活动房间、棋局和对话依旧不会跨插件重载恢复。

WebUI 的身份区域可以取消当前浏览器信任；在 QQ 中发送 `/game 撤销网页绑定` 可以撤销该 QQ 的全部设备。撤销不会中断当前房间，但之后进入新房间需要重新使用一次性令牌。

## 陪伴联动

安装支持游戏事件扩展 API 的“我会永远陪着你”后，可以分别开启游戏情绪余韵和主动邀请。两项默认关闭；陪伴插件缺失、尚未加载或版本较旧时只跳过联动，不影响创建房间和进行游戏。

情绪余韵在每局结束后立即按实际玩家分别结算。事件只包含游戏、胜负、累计比分、难度和房间来源等结构化信息，不包含棋谱、隐藏汤底或其他玩家的对话。仅绑定后真正进入过玩家席的用户收到胜负余韵；匿名用户和仅旁观者不会参与结算。长期共同经历仍在房间销毁时按原规则汇总。

胜负余韵与陪伴插件已有的“受伤/拒绝”状态相互独立。陪伴人格可以很在乎输赢，也可以更在乎共同参与；连续胜负会累积，但竞争情绪和陪伴温度各自拥有由人格判断的上限与持续时间。WebUI 中提出“再来一局”时，陪伴插件会结合实际用语决定清除、缩短、保留或延长当前余韵。

主动邀请复用陪伴插件的主动消息链，不由游戏插件自行定时发送。开启后只注册一个候选能力，最终是否邀请仍受人格、日程、关系、免打扰、每日主动额度和冷却控制。邀请本身不会提前创建房间；用户明确接受后，仍由正常 QQ 对话中的游戏工具创建并发送链接。

## 贪心骰子

贪心骰子使用一颗六面骰。当前行动方掷出 2-6 时点数累加到本回合暂存分，可以继续掷或选择收手；收手会将暂存分加入总分并换人。掷出 1 时本回合暂存分全部丢失并立即换人，率先达到或超过 50 分的一方获胜。

每局先手由服务端随机决定。Bot 的稳健、均衡或大胆倾向由人格选择，但实际收手阈值还会根据领先或落后幅度、双方距离 50 分的距离动态调整。普通掷骰和决策不调用模型，仅在连续冒险、高分爆掉、大额存分及终局等节点触发人格化表达。

骰子点数使用服务端安全随机源生成，WebUI 只提交继续掷或收手操作，无法提交指定点数。Bot 每次掷骰会逐次公开并带轻微间隔，不会一次跳到最终结果。

## 海龟汤

海龟汤支持两种通过 WebUI 对话自然切换的玩法，页面不提供固定玩法选择按钮。两种玩法都使用最多 6 个玩家席，玩家按稳定访客序号轮流操作；每回合默认 60 秒，超时会跳到下一位在线玩家，模型出题或判断期间暂停倒计时。

“Bot 出题、玩家猜”沿用实时生成流程。玩家入席并开始后，Bot 输出结构化汤面、固定汤底、关键事实和渐进提示，再进行一次隐藏的自洽性校验。最多尝试三次，模型不可用或题目连续未通过校验时使用插件内置安全题。每次提问、完整猜测或提示申请都会消耗当前玩家的一回合。

对局开始后汤底保持冻结。当前玩家可以在 WebUI 对话区提出单个是非问题，公开裁决限定为“是、否、无关、部分正确”；复合问题会要求拆分。玩家也可以在对话区申请提示或提交完整推理，只有核心因果链和大部分关键事实命中才算成功解谜。放弃后会揭晓汤底，海龟汤不提供悔棋。

“玩家出题、Bot 猜”不要求玩家上传隐藏汤底。当前玩家在 WebUI 对话区提供第一条公开线索，之后轮流回答 Bot 的问题或补充线索；Bot 每回合只根据全部公开内容继续提问或提交完整猜测。Bot 猜中后由当前玩家在 WebUI 确认，避免模型提前接触答案，也避免用不可靠的字符串匹配判定胜负。

多人模式下，观众可以向指定玩家发送交换申请；同一观众默认 30 秒只能申请一次，一次只能有一条待处理申请，申请 20 秒后失效。目标玩家接受后双方原子交换位置，新玩家不会继承原玩家绑定的 QQ 身份；若交换当前回合席位，新玩家获得完整回合时间。

房间销毁时，共同经历和有限对话摘录会分别写给所有已绑定玩家，以及发言过的已绑定观众；匿名观众不会生成记忆。

进行中的公开房间快照只包含标题、汤面、已公开问答和提示，不包含汤底或关键事实。题目生成不读取用户长期记忆或生活场景，避免私人信息进入观众可见的汤面；房间结束时不会保存隐藏汤底。

## 中国象棋引擎

中国象棋使用 [Pikafish](https://github.com/official-pikafish/Pikafish) 提供合法着法校验、终局判断和 Bot 走棋。插件不会导入第三方象棋规则 Python 库；Pikafish 作为独立进程运行。引擎不可用时只影响象棋，五子棋仍可正常创建和游玩。

默认允许管理员从游戏管理台按需安装，但不会自动下载。安装流程会：

1. 从 Pikafish 官方 GitHub Releases 读取最新发行版。
2. 下载 `.7z` 资产并校验 GitHub 提供的 SHA-256。
3. 只提取当前平台需要的可执行文件、`pikafish.nnue` 和许可证文件。
4. 在插件数据目录中原子替换托管版本，并执行 UCI 启动检查。

下载最多允许 160 MiB。可通过 `xiangqi.download_proxy` 显式设置 HTTP 代理；留空时继承进程的 `HTTPS_PROXY` 或 `HTTP_PROXY`。也可以设置 `xiangqi.engine_path` 使用自行安装的二进制，此时 `pikafish.nnue` 必须位于可执行文件同目录。

自动安装支持 Linux x86_64、Windows x86_64 和 macOS Apple Silicon；其他平台可以配置兼容的自备引擎。Pikafish 使用 GPL-3.0，NNUE 文件具有单独许可；官方许可证会随托管安装保存在插件数据目录。插件通过 `py7zr` 解压官方发行包。

象棋服务端以 Pikafish 返回的合法着法为准，采用 ICCS 坐标保存内存棋谱。无合法着法的一方判负；三次重复局面或连续 120 个半回合无吃子时判和。房间销毁或插件重载后不保存棋谱。

## 外部访问

房间服务默认按需监听 `127.0.0.1:6331`。如果端口已被占用，只会尝试后续十个端口，不会关闭或复用其他服务。

推荐二选一：

1. 在 `server.public_base_url` 配置现有 HTTPS 反向代理地址。
2. 安装 `cloudflared`，保留 `server.auto_quick_tunnel=true`，创建首个房间时按需生成 `trycloudflare.com` 临时 HTTPS 地址。

插件不会自动下载 `cloudflared`、修改防火墙、执行 UPnP 或退回到公开服务器 IP。

Quick Tunnel 首次启动后会保持到插件卸载或管理员在管理台手动停止，房间超时销毁不会让旧链接直接变成 Cloudflare 1033。已销毁房间的关闭原因只在内存中短期保留，旧链接会显示房间已经结束或过期。存在活动房间时如果 `cloudflared` 意外退出，插件会按间隔自动重建通道，并在原 QQ 会话发送新链接；临时域名发生变化后，旧消息中的链接无法继续使用。

反向代理需要将完整 HTTP 路径转发至实际监听端口。固定外部地址必须使用 HTTPS。

## 配置默认值

| 配置 | 默认值 | 说明 |
|---|---:|---|
| 允许群聊创建 | 开启 | 总开关关闭后管理员也不能创建 |
| 允许私聊创建 | 开启 | 私聊总开关 |
| 非管理员群聊创建 | 关闭 | 开启后普通群成员可创建 |
| 全部群聊房间上限 | 1 | `0` 为无限制 |
| 全部私聊房间上限 | 1 | `0` 为无限制 |
| 玩家席无人超时 | 60 秒 | `0` 关闭该项自动销毁 |
| 无有效操作超时 | 300 秒 | `0` 关闭该项自动销毁 |
| 允许管理台下载 Pikafish | 开启 | 可完全关闭托管下载 |
| 首次象棋房间自动下载 | 关闭 | 推荐在管理台确认后安装 |
| 海龟汤每题最多提示 | 3 | `0` 为允许查看全部预生成提示 |
| 海龟汤内容等级 | `normal` | 可选全年龄、普通或不限制 |
| 海龟汤最大玩家数 | 6 | `0` 为无限制 |
| 多人回合时间 | 60 秒 | `0` 关闭倒计时 |
| 交换申请冷却 | 30 秒 | `0` 不限制发送频率 |
| 交换申请有效期 | 20 秒 | 过期自动清理 |
| 游戏情绪余韵联动 | 关闭 | 需要兼容版本的“我会永远陪着你” |
| 陪伴主动邀请游戏 | 关闭 | 邀请不会自动创建房间 |
| 主动邀请候选权重 | 18% | 是相对动作权重，不是固定发送概率 |
| 主动邀请冷却 | 24 小时 | 由陪伴插件按用户分别记录 |

页面刷新、观众进出和状态轮询不算有效操作。

本局结束后，玩家关闭页面会发送离开通知；若 8 秒内没有重新进入，房间会提前销毁并释放名额。刷新或短暂页面切换可以在宽限期内恢复。浏览器未能发送离开通知时，玩家心跳中断 60 秒后兜底销毁。进行中或暂停中的棋局不使用这项快速销毁，仍按“无有效操作超时”处理。

## 开发验证

```bash
pytest -q
ruff check .
node --check web/app.js
node --check pages/游戏管理台/manager.js
```

最低支持 AstrBot `4.24.2`，当前开发与实机测试版本为 AstrBot `4.26.8`；需要 Python `3.12+`。插件版本为 `0.2.0`。
